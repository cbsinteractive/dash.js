# CMCD: Upgrade to `@svta/cml-cmcd` 2.4.0

**Status:** Design approved, ready for implementation plan
**Date:** 2026-05-27
**Branch:** `claude/infallible-mendeleev-493f12`

## Summary

Bump `@svta/cml-cmcd` from `2.3.2` to `^2.4.0` and adapt dash.js to the new `CmcdReporter` semantics. The headline change in 2.4.0 is that `CmcdReporter.update()` now auto-fires the corresponding state-change event (`PLAY_STATE`, `PLAYBACK_RATE`, `CONTENT_ID`, `BACKGROUNDED_MODE`, `BITRATE_CHANGE`) when a tracked field's value changes, and a follow-up `recordEvent()` call for the same event is dedup-suppressed — silently dropping enrichment data. The existing dash.js `update({ sta }) + recordEvent('ps', cmcdData)` pattern in `CmcdController._onPlaybackStateChange` hits this footgun and loses `bl`/`mtp`/`pt`/`ltc`/`msd` enrichment under 2.4.0.

This PR also replaces the local `CmcdRequestCollector` functional-test helper with `CmcdReportRecorder`, a new test helper shipped by `@svta/cml-cmcd` 2.4.0 with the same intent and a broader feature set.

## Background

### Library API changes in 2.4.0

From the v2.4.0 CHANGELOG and PR #375 documentation clarifications:

- `CmcdReporter.update()` auto-fires the corresponding state-change event when a tracked field changes. The state-change fields and their event tokens:
  - `sta` → `ps` (PLAY_STATE)
  - `pr` → `pr` (PLAYBACK_RATE) — new event type in 2.4.0
  - `cid` → `c` (CONTENT_ID)
  - `bg` → `b` (BACKGROUNDED_MODE)
  - `br` → `bc` (BITRATE_CHANGE)
- A follow-up `recordEvent()` for the same state-change event is dedup-suppressed — the second call's `data` argument is silently dropped.
- Consecutive same-value state-change events are suppressed (matches CTA-5004-B's definition of these events as transitions).
- `recordEvent()` with a state-change event now persists the dedup field into the data store (write-through), keeping the persistent store consistent with the most recently reported value.
- `prepareCmcdData` now force-includes the spec-required field for each state-change event after the `enabledKeys` filter — fixes CTA-5004-B-non-compliant payloads (CML #368, #372).

### Canonical usage pattern under 2.4.0

From the updated user guide:

- **State-change events** are fired via `update()`. Snapshot context is attached either by combining continuous metrics with the state field in a single call (`update({ sta: 'p', bl: [3000], mtp: [8500] })`) or by persisting continuous metrics via earlier `update()` calls.
- **Non-state-change events** (custom, error, ad lifecycle, mute/unmute, expand/collapse, skip) use `recordEvent()`. Its `data` argument should carry only payload intrinsic to the event call.
- **`TIME_INTERVAL` reports** draw exclusively from the persistent data store; there is no caller hook for per-event data. Fields the player wants in periodic reports must be kept fresh via `update()`.

### `CmcdReportRecorder` (new)

`CmcdReportRecorder` is shipped from `@svta/cml-cmcd` as the official test helper for capturing CMCD-bearing requests across XHR and `fetch`. It supersedes dash.js's locally maintained `CmcdRequestCollector`. Public surface:

```typescript
class CmcdReportRecorder {
    attach(options?: CmcdReportRecorderOptions): void;
    clear(): void;
    detach(): void;
    getReports(): CmcdRecordedReport[];
    waitForEvents(options?: CmcdReportRecorderWaitOptions): Promise<CmcdRecordedReport[]>;
    waitForManifest(options?: CmcdReportRecorderWaitOptions): Promise<CmcdRecordedReport[]>;
    waitForReports(options?: CmcdReportRecorderWaitOptions): Promise<CmcdRecordedReport[]>;
    waitForSegments(options?: CmcdReportRecorderWaitOptions): Promise<CmcdRecordedReport[]>;
}

type CmcdReportRecorderOptions = {
    eventTargetUrls?: readonly string[];
    transports?: readonly CmcdTransportAdapter[];
    waitTimeout?: number;
    onReport?: (report: CmcdRecordedReport) => void;
};

type CmcdReportRecorderWaitOptions = { count?: number; timeout?: number };

type CmcdRecordedReport = {
    readonly request: HttpRequest;
    readonly type: CmcdRecordedRequestType;       // MANIFEST | SEGMENT | EVENT | UNKNOWN
    readonly reportingMode: CmcdRecordedReportMode; // QUERY | HEADER | EVENT
    readonly timestamp: number;
};
```

## Goals

1. Adopt `@svta/cml-cmcd` 2.4.0 cleanly — no silent enrichment loss on state-change events.
2. Audit and align every `cmcdReporter.update()` / `recordEvent()` call site with the 2.4.0 canonical pattern (continuous metrics via `update()`, per-event ephemeral data via `recordEvent()`).
3. Replace the locally maintained `CmcdRequestCollector` with `CmcdReportRecorder` from the library.
4. Make `TIME_INTERVAL` reports useful by keeping continuous metrics fresh in the reporter's persistent data store, including `pt` (currently not reported by dash.js at all).

## Non-goals

- Refactoring `CmcdModel.getEventModeData()` internals beyond what is required by the above goals.
- Changing the public dash.js settings shape or the `CMCD_DATA_GENERATED` event payload.
- Adopting any other new 2.4.0 features beyond `CmcdReportRecorder` (e.g., custom transport adapters for non-XHR/fetch HTTP clients).

## Design

### 1. State-change consolidation

Replace the `update({ sta }) + triggerCmcdEventMode(PLAY_STATE)` pattern with a single consolidated `update()` call that auto-fires the event with the full enriched payload.

```js
function _onPlaybackStateChange(state) {
    if (!cmcdReporter) return;
    _rebuildReporterIfNeeded();
    cmcdReporter.update({ ..._gatherContinuousMetrics(), sta: state });
}
```

The continuous-metric helper centralizes the snapshot pulled from `CmcdModel`:

```js
function _gatherContinuousMetrics() {
    return {
        ...cmcdModel.getEventModeData(),  // ltc, bg, df, bl, mtp, ab, eb, pb, tb
        ...cmcdModel.calculateMsd(),       // msd (send-once gated by model)
    };
}
```

Note: `pt` is not in `_gatherContinuousMetrics()` because it lands in the reporter's persistent store via a dedicated throttled listener (Section 3). It's still emitted alongside the state-change event because the store carries it.

### 2. Non-state event helper

Rename `triggerCmcdEventMode` → `_recordNonStateEvent` to reflect its 2.4.0-aligned purpose. Continuous metrics flow through `update()` (persistent store); only ephemeral per-event data rides `recordEvent()`'s `data` argument.

```js
function _recordNonStateEvent(event, transientData = {}) {
    if (!cmcdReporter) return;
    _rebuildReporterIfNeeded();

    cmcdReporter.update(_gatherContinuousMetrics());  // persist into store
    cmcdReporter.recordEvent(event, transientData);   // ephemeral keys only
}
```

ERROR site becomes:

```js
function _onPlayerError(errorData) {
    if (errorData.error?.data?.request?.type === HTTPRequest.CMCD_EVENT) return;
    const code = errorData.error?.code || errorData.error?.data?.code;
    _recordNonStateEvent(
        Constants.CMCD_REPORTING_EVENTS.ERROR,
        code ? { ec: [code] } : {}
    );
}
```

`ec` becomes a `string[]` (matches the 2.4.0 `Cmcd.ec?: string[]` type and CTA-5004-B's list notation).

### 3. Continuous `pt` via throttled listener

`pt` (playhead time, ms) is not currently reported anywhere in dash.js. Add it via a throttled listener that writes directly to the reporter's persistent store. This makes `pt` available to both state-change auto-fires and `TIME_INTERVAL` reports without proliferating `update()` calls.

```js
const PT_UPDATE_THROTTLE_MS = 250; // 4 Hz; tunable
let _lastPtUpdateAt = 0;

function _onPlaybackTimeUpdated(e) {
    if (!cmcdReporter) return;
    const now = Date.now();
    if (now - _lastPtUpdateAt < PT_UPDATE_THROTTLE_MS) return;
    _lastPtUpdateAt = now;
    cmcdReporter.update({ pt: Math.round(e.time * 1000) });
}
```

Wiring:

- Subscribe in `_initializeEventBus`: `eventBus.on(MediaPlayerEvents.PLAYBACK_TIME_UPDATED, _onPlaybackTimeUpdated, instance);`
- Matching unsubscribe in `reset()`.
- Reset `_lastPtUpdateAt = 0` in `_resetInitialSettings()`.

Why this works:
- `pt` is not a state-change field, so `update({ pt })` doesn't auto-fire anything — the call just refreshes the store.
- State-change events auto-fire pull `pt` from the store along with the rest of the payload.
- `TIME_INTERVAL` ticks pull from the store; worst-case staleness is the throttle window (~250ms), below the granularity of any reasonable interval.
- Reporter dedup is a no-op for `pt` during playback (always changing), but the cost of `update()` is just a Map write — negligible at 4 Hz.

### 4. Hybrid continuous persistence (audit findings)

The following fields are continuous and reach the persistent store via the design above:

| Field | Source | Mechanism |
|---|---|---|
| `pr` | `MediaPlayerEvents.PLAYBACK_RATE_CHANGED` | Already wired via `_onPlaybackRateChanged` → `update(prData)`. Now also auto-fires PLAYBACK_RATE event (intentional). |
| `st`, `sf` | `MediaPlayerEvents.MANIFEST_LOADED` | Already wired via `_onManifestLoaded` → `update(streamFormatInfo)`. |
| `msd` | `calculateMsd()` (send-once gated) | Already routed through `update()`; flows in via `_gatherContinuousMetrics()`. |
| `bl`, `mtp`, `ab`, `eb`, `pb`, `tb`, `ltc`, `bg`, `df` | `CmcdModel.getEventModeData()` (on-demand) | Flows in via `_gatherContinuousMetrics()` at each state-change and non-state event site; lands in the persistent store, so `TIME_INTERVAL` reports between events still see recent values. |
| `pt` | `MediaPlayerEvents.PLAYBACK_TIME_UPDATED` (throttled) | New listener writes directly to the store (Section 3). |

Inline-snapshot fields (per-request only, built in `deriveCmcdDataForRequest()`): `nor`, `nrr`, `d`, `ot`, `tb`, `dl`, `bs`, `rtp`, `su`. Unchanged.

`sn` is no longer tracked or set anywhere in dash.js — the reporter handles it internally. The only stale reference is the comment at [CmcdController.js:271](src/streaming/controllers/CmcdController.js:271): edit to drop "and sn".

Delete [test/functional/helpers/CmcdRequestCollector.js](test/functional/helpers/CmcdRequestCollector.js).

In [test/functional/test/feature-support/cmcd-v2.js](test/functional/test/feature-support/cmcd-v2.js) and [test/functional/test/feature-support/cmcd.js](test/functional/test/feature-support/cmcd.js), apply the API mapping:

| Old (`CmcdRequestCollector`) | New (`CmcdReportRecorder` from `@svta/cml-cmcd`) |

| `new CmcdRequestCollector()` | `new CmcdReportRecorder()` |

| `collector.getRequests('segment')` | `…filter((r) => r.type === CmcdRecordedRequestType.SEGMENT)` |
| `collector.getRequests('event')` | `…filter((r) => r.type === CmcdRecordedRequestType.EVENT)` |

| `r.reportingMode === 'header'` | `r.reportingMode === CmcdRecordedReportMode.HEADER` |

Timeout strategy: set `waitTimeout` once at `attach()`-level. Drop all per-call `timeout` arguments, including the lone `20000` at [cmcd-v2.js:399](test/functional/test/feature-support/cmcd-v2.js:399). Restore the longer timeout later only if a real test reliability issue surfaces.

Cosmetic: rename the `collector` local in each `before`/`after` block to `recorder` for clarity. Not load-bearing.

### 6. POST stub response handling

`CmcdReportRecorder` stubs POSTs to `eventTargetUrls` with a synthetic `204 No Content`. The old `CmcdRequestCollector` returned `200 OK`. The implementation plan should verify dash.js's `URLLoader` treats `204` as success. The relevant code is `_customRequester` at [CmcdController.js:219](src/streaming/controllers/CmcdController.js:219):

```js
urlLoader.load({
    request: httpRequest,
    success: () => resolve({ status: 200 }),
    error: (e) => resolve({ status: e?.status || 500 }),
});
```

If `URLLoader`'s success callback fires on any 2xx, no change needed. If it gates on `200` specifically, widen `_customRequester` to resolve `{ status: 204 }` on success without changing the public contract.

## Risk register (for PR description)

1. **PLAYBACK_RATE auto-fire is new behavior.** Pre-2.4.0, `update(prData)` did not emit. Post-2.4.0, it auto-fires a PLAYBACK_RATE event-mode report when an event target subscribes to it. This is correct per CTA-5004-B but is a visible behavior change for downstream consumers and should be flagged in release notes.
2. **`ec` shape change.** `recordEvent(ERROR, { ec: 'CODE' })` (single string) → `recordEvent(ERROR, { ec: ['CODE'] })` (array). Required by 2.4.0 typings and CTA-5004-B; no consumer of the dash.js public API depends on the wire-format shape, but downstream payload validators should accept array form.
3. **POST stub status code shift** (200 → 204) — see Section 6.
4. **Throttled `pt` updates** assume `PLAYBACK_TIME_UPDATED` fires at human-readable cadences. The 250 ms throttle bounds work even if the source ever fires per-frame.
5. **`CmcdRecordedRequestType.UNKNOWN`** classification — `CmcdReportRecorder` records CMCD-bearing requests that aren't manifest/segment/event as `UNKNOWN`, where the old collector silently dropped them. Test filters using `getReports().filter(r => r.reportingMode === 'query')` may now pick up additional entries; tests that intend media-only assertions should add a `type` filter.
