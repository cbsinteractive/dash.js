# `@svta/cml-cmcd` 2.4.0 Update Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `@svta/cml-cmcd` from 2.3.2 to ^2.4.0, fix the `update()` + `recordEvent()` enrichment-loss footgun in `CmcdController`, add throttled `pt` reporting via `PLAYBACK_TIME_UPDATED`, and replace the local `CmcdRequestCollector` functional-test helper with the library's `CmcdReportRecorder`.

**Architecture:** A single consolidated `update()` call carries continuous metrics + the state field, letting the reporter's new auto-fire behavior emit the full enriched payload. A dedicated throttled listener writes `pt` to the persistent store so both auto-fired state events and `TIME_INTERVAL` reports see fresh values. The non-state-event helper (formerly `triggerCmcdEventMode`, now `_recordNonStateEvent`) persists continuous metrics through `update()` and reserves the `recordEvent()` `data` argument for ephemeral per-event payload only (e.g., `ec`).

**Tech Stack:** dash.js (ES modules, FactoryMaker), `@svta/cml-cmcd` 2.4.0 (`CmcdReporter`, `CmcdReportRecorder`), karma + mocha + chai + sinon for unit tests, karma functional tests against real MPDs.

**Spec:** [`docs/superpowers/specs/2026-05-27-cmcd-v2.4-update-design.md`](../specs/2026-05-27-cmcd-v2.4-update-design.md) (commit `6f004ba1a`).

```js
/**
 * Records a non-state-change event (e.g., ERROR, custom). Continuous
 * metrics are persisted into the reporter's data store via update();
 * only ephemeral per-event payload (e.g., ec for ERROR) is passed
 * through recordEvent()'s data argument.
 *
 * State-change events (ps, pr, c, b, bc) auto-fire from update() and
 * MUST NOT be routed through this helper — a follow-up recordEvent()
 * for the same event token is dedup-suppressed under
 * @svta/cml-cmcd >= 2.4.0.
 *
 * @param event - Event token (e.g., Constants.CMCD_REPORTING_EVENTS.ERROR)
 * @param transientData - Per-event payload that should NOT persist into
 *                        the reporter's data store.
 */
function _recordNonStateEvent(event, transientData = {}) {
    if (!cmcdReporter) {
        return;
    }
    _rebuildReporterIfNeeded();

    cmcdReporter.update(_gatherContinuousMetrics());
    cmcdReporter.recordEvent(event, transientData);
}
```

## Risk register (for PR description)

When opening the PR, surface these behavior deltas in the description:

1. **PLAYBACK_RATE auto-fire is new.** Pre-2.4.0, `CmcdReporter.update(prData)` did not emit. Post-2.4.0, it auto-fires a PLAYBACK_RATE event-mode report when an event target subscribes to it. Correct per CTA-5004-B; a visible behavior change for downstream consumers.
2. **`ec` shape change.** ERROR event payloads now carry `ec` as `string[]` (was a scalar). Required by 2.4.0 typings and CTA-5004-B's list notation.
3. **POST stub status code shift** (200 → 204) — handled transparently because `HTTPLoader` already treats any 2xx as success.
4. **`CmcdRecordedRequestType.UNKNOWN`** — the new recorder also records CMCD-bearing requests that aren't manifest/segment/event. Test filters using `getReports().filter(r => r.reportingMode === ...)` may pick up additional entries; the migrated tests filter by `type` where they care about media-only data.
